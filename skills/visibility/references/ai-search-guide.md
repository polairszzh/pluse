# AI 平台引用机制与优化策略

> Updated: 2026-08-04

## 核心原则

AI 搜索平台的引用机制与传统 SEO 排名机制有根本不同：
- **传统 SEO**：优化页面 → 争取排名 → 用户点击
- **AI 搜索**：AI 综合全网信息 → 生成答案 → 引用来源（用户可能不点击任何链接）

优化目标是**被引用**，而不是**被点击**。

## 各平台引用特征

### DeepSeek
- **引用倾向**：技术/学术内容、GitHub 项目、知乎高赞回答、中文技术博客
- **引用偏好**：有代码示例、有数据对比、有明确结论的内容
- **API 可用性**：有公开 API，可直接查询

### Kimi（月之暗面）
- **引用倾向**：长文分析、研究报告、知乎深度回答
- **引用偏好**：结构清晰（H2/H3 分明）、有数据支撑、有方法论框架的内容
- **API 可用性**：无公开 API，需通过网页搜索推断

### 豆包（字节跳动）
- **引用倾向**：头条号内容、抖音生态、百科类来源
- **引用偏好**：简洁实用、有步骤指引、生活化语言的内容
- **API 可用性**：无公开 API

### 元宝（腾讯）
- **引用倾向**：微信公众号、知乎、腾讯新闻
- **引用偏好**：综合类内容、生活百科、产品评测
- **API 可用性**：无公开 API

## Passage Citability 评分标准

AI 模型倾向于引用**自包含的、130-170 字的段落**。太短缺乏上下文，太长模型难以完整摘取。

### 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 长度适配 | 25% | 130-170 字最佳，100-200 字可接受 |
| 自包含性 | 30% | 脱离上下文能否独立理解 |
| 数据支撑 | 20% | 是否包含具体数字、百分比、时间节点 |
| 引用性 | 15% | 是否被其他来源交叉引用 |
| 问题-答案匹配 | 10% | 段落是否直接回答了某个具体问题 |

## 优化策略

### 1. 问题导向的内容结构
- 每个 H2 是一个用户可能问的问题
- H2 下面的第一段直接回答问题（自包含答案块）
- 后续段落提供细节和证据

### 2. 提升实体存在感
AI 引用一个品牌/内容的前提是它在训练/检索数据中"认识"这个实体。提升实体存在感的渠道：
- Wikipedia / 百度百科条目
- 知乎话题页面
- GitHub 仓库（对技术产品）
- Reddit / Hacker News 讨论（对出海产品）
- 权威媒体的报道或引用

### 3. 被引用 ≠ 被推荐
- AI 可能引用你的内容但对它持批评态度（中性/负面引用）
- 需要同时追踪**引用率**和**引用情感**
- 负面引用可能是竞品内容或用户投诉导致的

## 常见误区

1. **"llms.txt 能提升 AI 引用率"** — 目前没有证据表明 llms.txt 是 AI 平台的引用信号。Google 已明确表示忽略 llms.txt。

2. **"内容分块（chunking）能让 AI 更容易抓取"** — AI 平台的检索系统会自己做分块，不需要内容创作者手动分块。过度分块反而可能破坏内容的连贯性。

3. **"需要为 AI 写特殊的、带关键词的版本"** — AI 平台的语义理解能力很强，同义词和理解能力足够。正常的、清晰的写作就是最好的"AI 优化版"。
